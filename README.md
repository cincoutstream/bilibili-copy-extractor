## 概述

把 B站视频的官方字幕导出为 Markdown 文档：每个视频一个 md 文件，另附一份可跳转的索引与一份可供程序读取的清单。字幕取自 B站提供的人工 CC 字幕或 AI 自动生成字幕，有人工 CC 字幕时优先使用，没有时回退到 AI 字幕。工具只读取 B站已有的字幕数据，不进行语音识别。

字幕语言以 B站提供的字幕轨为准。绝大多数视频为中文，个别视频由 UP 主上传了其他语言。

## 可用功能

左栏是提取场景，右栏是可直接发给 agent 的说法。

| 场景 | 请求示例 |
|---|---|
| 单个视频 | 把这个视频的字幕导出成文案：<视频链接> |
| UP 主最近若干条 | 把「某某」最近 10 条视频的字幕导出成文案 |
| UP 主全部投稿 | 把「某某」的全部投稿导出成文案 |
| 按点赞数取前若干条 | 把「某某」点赞最多的 10 条视频导出成文案 |
| 按播放量取前若干条 | 把「某某」播放最多的 10 条视频导出成文案 |
| 指定日期区间 | 把「某某」2026 年 10 月的视频导出成文案 |
| 指定合集或系列 | 把「某某」的《某某系列》导出成文案 |
| 查看有哪些合集 | 列出「某某」的合集与系列 |
| 只列清单不导出 | 先列出「某某」最近 10 条视频的标题，确认后再导出 |
| 追加到已有文件夹 | 把「某某」最近 15 条追加到上次那个文案文件夹 |
| 打包与时间轴 | 导出后打包成 zip，并附带字幕时间轴文件 |
| 中断后继续 | 上次中途停止了，从已完成的位置继续 |
| 指定保存位置 | 把结果保存到 D:\资料 |

UP 主可以用名称、uid 或空间主页链接指明。默认输出到工作目录下的 `bili文案` 文件夹，也可以指定其他位置。

## 环境要求

已安装 Python 3.7 或更高版本。

## 安装

### 方式一：交给 agent 安装

在对话中发送下面这段内容，由 agent 完成安装：

```
请把 https://github.com/cincoutstream/bilibili-copy-extractor 安装为你的技能。
它包含 SKILL.md 与 scripts/bili_copy.py，安装完成后请说明可以用哪些说法让我提取 B站视频的文案。
```

这种方式不绑定具体的 agent 工具，凡支持安装技能的 agent 均可执行。

### 方式二：SkillHub

```
skillhub install bilibili-copy-extractor
```

### 方式三：手动放置

从仓库获取源码，将整个目录放入所用 agent 工具的技能目录。目录位置以该工具的文档为准。

## 凭据与安全

整个流程只需要一项凭据：使用者本人 B站账号的 `SESSDATA` cookie。

B站只向已登录的请求返回字幕地址。未登录时请求可以成功，但字幕列表为空。这是 B站服务端的限制，与提取工具无关。

获取步骤：

1. 在浏览器中登录 `bilibili.com`，按 F12 打开开发者工具
2. 进入 Application，选择 Cookies，域名选 `https://www.bilibili.com`
3. 复制 `SESSDATA` 一行的 Value
4. 把复制到的值发给 agent，由 agent 保存在本机使用

该值等同于账号登录凭据，不要粘贴到聊天群或公开渠道。凭据只保存在本机，不写入日志，也不会在终端或对话中回显。提取完成后可以让 agent 清除，或在 B站执行退出登录使其立即失效。

## 输出结构

每次提取生成一个文件夹：

```
<UP主>_最近10条视频文案_20261031/
    01_<视频标题>_2026-10-31.md
    02_<视频标题>_2026-10-30.md
    _index.md        可排序的表格，可跳转到每个文件
    _manifest.json   同一份数据的机器可读版本
    _progress.json   断点续跑记录，请勿手工编辑
```

文件夹名与文件名使用中文，与来源站点的界面语言一致。每个 md 文件开头是一段字段区，记录 bvid、标题、UP 主、发布时间、时长、播放、点赞、收藏、投币、弹幕、评论数、字幕来源、字数与覆盖率，其后为分段后的正文。需要打包时，zip 文件生成在文件夹同级。

## 命名规则

批量提取的文件夹名由 UP 主、批次说明与生成日期组成；单个视频另用一套命名：

| 场景 | 文件夹名示例 |
|---|---|
| 单个视频 | `<UP主>_2026-10-31_<视频标题>` |
| 最近 N 条 | `<UP主>_最近10条视频文案_20261031` |
| 最早 N 条 | `<UP主>_最早10条视频文案_20261031` |
| 全部投稿 | `<UP主>_全部N条视频文案_20261031` |
| 点赞最多 | `<UP主>_点赞最多10条视频文案_20261031` |
| 播放最多 | `<UP主>_播放最多10条视频文案_20261031` |
| 日期区间 | `<UP主>_2026-10-20至2026-10-25视频文案_20261031` |
| 合集或系列 | `<UP主>_合集-<合集名>视频文案_20261031` |

文件名为 `{序号}_{标题}_{发布日期}.md`：

| 组成 | 规则 |
|---|---|
| 序号 | 该批次内的排名，与索引表格的顺序一致，因此在文件管理器中按名称排列即等于排名顺序。不足两位时补零，条目超过 99 条时按实际位数顺延 |
| 标题 | 紧接序号，最长 50 字。Windows 文件名保留字符 `\ / : * ? " < > \|` 替换为下划线 |
| 日期 | 置于末尾，浏览目录即可看到发布日期，无需打开文件 |

## 追加到已有文件夹

默认每次提取都新建文件夹。需要把新提取的视频并入已有文件夹时，在请求中说明追加到哪个文件夹，输出会写入同一个文件夹，不再新建批次目录。

追加时按以下规则处理：

| 情形 | 行为 |
|---|---|
| 视频已存在于文件夹 | 按 bvid 去重后跳过，不重复提取 |
| 新条目编号 | 接在现有最大序号之后，既有文件不改名 |
| 索引与清单文件 | 合并新旧条目后整体重写 |
| 文件夹名 | 保持不变，不随条数变化。名为「最近10条」的文件夹最终可以有 15 份文件 |
| 指定的文件夹不存在 | 自动创建，可作为长期积累的项目目录 |

未说明追加位置时，按批次规则新建文件夹。

## 排序方式与耗时

| 排序方式 | 耗时 | 说明 |
|---|---|---|
| 最新若干条、最早若干条 | 最短，只取指定条数 | 无需遍历整份投稿列表 |
| 按播放量 | 投稿越多耗时越长 | 需要遍历整份列表才能确定播放量最高的一条 |
| 按点赞数 | 条数越多耗时越长 | 点赞数不在列表数据中，需要逐条读取统计。默认在最近 200 条范围内挑选候选，可以指定更大的范围 |

单次提取超过 100 条，以及按点赞数排序且候选超过 400 条时，工具会先给出预计情况并请求确认。

整份投稿列表的结果会缓存 30 分钟。有效期内重复提取同一 UP 主会直接复用，无需重新获取。

## 已知限制

- AI 字幕需要先生成。B站要等到有用户在播放器中选择「字幕 → 中文」后才会生成该字幕，首次约 10 至 30 秒，之后对所有使用者可用。取不到时会在文件夹内写入一份说明文件并记入索引，在播放器中触发一次后重新提取即可。
- 同音错字来自 B站自身的转写结果，不属于提取错误。精修需要另加一道语言模型处理。
- 部分 AI 字幕不带标点。工具按句末标点、话语标记词与虚词边界恢复分段。
- 接口存在频率限制。同时处理的数量过多会触发风控，表现为请求被拒绝。此时等待数分钟后重试，或减少同时处理的数量、分批次提取。

## 常见错误

| 现象 | 原因与处理 |
|---|---|
| 字幕列表为空 | 未提供 SESSDATA，或该值已过期，重新获取后重试 |
| 请求被拒绝，返回 412 或 -352 | 触发 B站风控，等待数分钟后重试，或减少同时处理的数量、分批次提取 |
| 合集只取到 1 集 | 合集名称未匹配。先让 agent 列出该 UP 主的合集与系列，再用准确名称提取 |
| 提取条数少于预期 | 核对指定的条数。日期区间模式会自动扩量，其余模式严格按指定条数取 |
