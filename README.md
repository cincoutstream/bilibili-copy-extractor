## 概述

把 B站视频的官方字幕导出为 Markdown 文档：每个视频一个 md 文件，另附一份可跳转的索引与一份可供程序读取的清单。字幕取自 B站提供的人工 CC 字幕或 AI 自动生成字幕，有人工 CC 字幕时优先使用，没有时回退到 AI 字幕。工具只读取 B站已有的字幕数据，不进行语音识别。

字幕语言以 B站提供的字幕轨为准。绝大多数视频为中文，个别视频由 UP 主上传了其他语言。

## 亮点

| 亮点 | 说明 |
|---|---|
| 使用官方字幕 | 取 B站提供的人工 CC 字幕或 AI 自动生成字幕，不重新识别语音，用词与站内保持一致 |
| 一句话批量提取 | 说明 UP 主与条数即可连续处理，无需逐条粘贴视频链接 |
| 产物可直接阅读 | 每个视频一个 Markdown 文件，开头记录标题、发布时间、播放与点赞等数据，其后是分段正文 |
| 目录即索引 | 序号在前、发布日期在后，按名称排序即按排名浏览；另有可点击跳转的索引表 |
| 支持排名与合集 | 可按点赞或播放量取前若干条，也可只提取某个合集或系列 |
| 中断后可继续 | 批量中途停止后重新发起，已完成的视频会跳过 |
| 结果可打包 | 需要时打包成 zip，并可附带字幕时间轴文件 |

## 可用功能

左栏是提取场景，右栏是可直接发给 agent 的说法。

| 场景 | 请求示例 |
|---|---|
| 单个视频 | 把这个视频的字幕导出成文案：<视频链接> |
| UP 主最近若干条 | 把 <UP主> 最近 10 条视频的字幕导出成文案 |
| UP 主全部投稿 | 把 <UP主> 的全部投稿导出成文案 |
| 按点赞数取前若干条 | 把 <UP主> 点赞最多的 10 条视频导出成文案 |
| 按播放量取前若干条 | 把 <UP主> 播放最多的 10 条视频导出成文案 |
| 指定日期区间 | 把 <UP主> 2026 年 10 月的视频导出成文案 |
| 指定合集或系列 | 把 <UP主> 的 <系列名称> 导出成文案 |
| 查看有哪些合集 | 列出 <UP主> 的合集与系列 |
| 只列清单不导出 | 先列出 <UP主> 最近 10 条视频的标题，确认后再导出 |
| 追加到已有文件夹 | 把 <UP主> 最近 15 条追加到上次那个文案文件夹 |
| 打包与时间轴 | 导出后打包成 zip，并附带字幕时间轴文件 |
| 中断后继续 | 上次中途停止了，从已完成的位置继续 |
| 指定保存位置 | 把结果保存到 D:\资料 |

`<UP主>` 处填 UP 主名称、uid 或空间主页链接均可。默认输出到工作目录下的 `bili文案` 文件夹，也可以指定其他位置。

## 环境要求

已安装 Python 3.7 或更高版本。

## 安装

### 方式一：交给 agent 安装

在对话中发送下面这段内容，由 agent 完成安装：

```
请把 bilibili-copy-extractor 安装为你的技能。
优先从 GitHub 获取：https://github.com/cincoutstream/bilibili-copy-extractor
如果 GitHub 打不开，就从 SkillHub 安装同名技能：skillhub install @user_c14bff27/bilibili-copy-extractor
它包含 SKILL.md 与 scripts/bili_copy.py，安装完成后请说明可以用哪些说法让我提取 B站视频的文案。
```

这种方式不绑定具体的 agent 工具，凡支持安装技能的 agent 均可执行。GitHub 在部分网络环境下无法访问，此时改用 SkillHub 的同名包，两者内容一致。

### 方式二：自己安装

从 SkillHub 安装：

```
skillhub install @user_c14bff27/bilibili-copy-extractor
```

或从仓库获取源码，将整个目录放入所用 agent 工具的技能目录。目录位置以该工具的文档为准。

## 凭据与安全

整个流程只需要一项凭据：使用者本人 B站账号的 `SESSDATA` cookie。

B站只向已登录的请求返回字幕地址。未登录时请求可以成功，但字幕列表为空。这是 B站服务端的限制，与提取工具无关。

获取步骤：

1. 在浏览器中登录 `bilibili.com`，按 F12 打开开发者工具
2. 进入 Application，选择 Cookies，域名选 `https://www.bilibili.com`
3. 复制 `SESSDATA` 一行的 Value
4. 把复制到的值发给 agent，由 agent 保存在本机使用

该值等同于账号登录凭据，不要粘贴到聊天群或公开渠道。凭据只保存在本机，不写入日志，也不会在终端或对话中回显。提取完成后可以让 agent 清除，或在 B站执行退出登录使其立即失效。

## 使用实例

以下是一次完整提取的过程。

1. 把需求交给 agent。只提取一个视频时，给出链接即可：

```
把这个视频的字幕导出成文案：https://www.bilibili.com/video/BV1xx411c7mD
```

按 UP 主批量提取时，说清对象与条数：

```
把 <UP主> 点赞最多的 10 条视频导出成文案
```

2. 首次使用时提供凭据。按上一节步骤复制 `SESSDATA`，直接发给 agent，之后不必重复提供。

3. 等待完成。批量提取会逐条处理，条数较多时需要等待一段时间。单次超过 100 条，或按点赞排序且候选超过 400 条时，会先给出预计情况并请求确认。

4. 取回产物。结果位于工作目录下的 `bili文案` 文件夹：

```
<UP主>_点赞最多10条视频文案_20261031/
    01_<视频标题>_2026-10-31.md
    02_<视频标题>_2026-10-29.md
    _index.md
```

打开 `_index.md` 可以看到按排名排列的表格，点击即可跳到对应文件；需要整包带走时，把上面这个文件夹打包即可。

若某个视频取不到字幕，通常是 B站尚未生成该视频的 AI 字幕：在播放器中打开该视频，点一次「字幕 → 中文」，再让 agent 重试即可。

## 输出结构

每次提取生成一个文件夹：

```
<UP主>_最近10条视频文案_20261031/
    01_<视频标题>_2026-10-31.md
    02_<视频标题>_2026-10-30.md
    _index.md        可排序的表格，可跳转到每个文件
    _manifest.json   同一份数据的机器可读版本
    _progress.json   断点续跑记录，请勿手工编辑
```

文件夹名与文件名使用中文，与来源站点的界面语言一致。每个 md 文件开头是一段字段区，记录 bvid、标题、UP 主、发布时间、时长、播放、点赞、收藏、投币、弹幕、评论数、字幕来源、字数与覆盖率，其后为分段后的正文。需要打包时，zip 文件生成在文件夹同级。

## 命名规则

批量提取的文件夹名由 UP 主、批次说明与生成日期组成；单个视频另用一套命名：

| 场景 | 文件夹名示例 |
|---|---|
| 单个视频 | `<UP主>_2026-10-31_<视频标题>` |
| 最近 N 条 | `<UP主>_最近10条视频文案_20261031` |
| 最早 N 条 | `<UP主>_最早10条视频文案_20261031` |
| 全部投稿 | `<UP主>_全部N条视频文案_20261031` |
| 点赞最多 | `<UP主>_点赞最多10条视频文案_20261031` |
| 播放最多 | `<UP主>_播放最多10条视频文案_20261031` |
| 日期区间 | `<UP主>_2026-10-20至2026-10-25视频文案_20261031` |
| 合集或系列 | `<UP主>_合集-<合集名>视频文案_20261031` |

文件名为 `{序号}_{标题}_{发布日期}.md`：

| 组成 | 规则 |
|---|---|
| 序号 | 该批次内的排名，与索引表格的顺序一致，因此在文件管理器中按名称排列即等于排名顺序。不足两位时补零，条目超过 99 条时按实际位数顺延 |
| 标题 | 紧接序号，最长 50 字。Windows 文件名保留字符 `\ / : * ? " < > \|` 替换为下划线 |
| 日期 | 置于末尾，浏览目录即可看到发布日期，无需打开文件 |

往已有文件夹里追加时，文件夹名保持不变，新条目接在现有最大序号之后，已存在的视频不会重复提取。
